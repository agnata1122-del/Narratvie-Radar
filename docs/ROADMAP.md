# 로드맵

PRD 19장(Phase)과 23장(Step)을 따르되, 섀도 테스트용 포워드 데이터를 하루라도 빨리 쌓기 위해 수집기를 앞당겼다([DECISIONS.md](DECISIONS.md) D2). 첫 소스는 공식 API가 있는 Bluesky와 Hacker News다(D15). 디시·네이버는 데이터 이용 문의 회신 후 추가한다.

첫 데모 목표: 같은 관심사를 며칠 뒤 다시 열었을 때, 무엇이 달라졌고 왜 그렇게 말할 수 있는지를 근거와 함께 바로 이해한다.

## 체크포인트

1. **M3 이후**: 수집기가 24시간 연속으로 돌고, 누락률·스냅샷 재방문 성공률·공백 기록을 확인한다.
2. **M7 이후**: 명령줄만으로 수집 → 분류 → 그래프 → 위키 → 시점 복원이 끝까지 돌고, 평가 리포트가 나온다.
3. **M9 이후**: 브라우저에서 "달라진 점"과 시간 재생 화면을 스크린샷으로 확인한다.

## 시작 전에 필요한 것

- **네트워크 허용** (M2): 개발 환경에서 `jetstream1.us-east.bsky.network`, `jetstream2.us-east.bsky.network`, `hn.algolia.com`, `hacker-news.firebaseio.com`에 접속할 수 있어야 한다. 안 되면 확인 명령은 로컬 PC에서 실행한다.
- **데이터 보관** (M3): 세션 사이에 수집 데이터를 보관할 비공개 저장소. 정기 수집은 그 저장소의 GitHub Actions가 한다(DECISIONS D32).

## D34 이후: 가지 → 열매 로드맵 (2026-10-18 작성, 미착수)

각 단계는 앞 단계의 검증 기준을 넘어야 시작한다. 기준은 시작 전에 고정하고 결과를 보고 바꾸지 않는다.

| 단계 | 내용 (재사용 → 최소 추가) | 검증 기준 |
|---|---|---|
| R0 | **E1 품질 확인** (진행 중): 무작위 50건, 주장 표본 50개, 메모리 review 67건 | 50건 정확도 ≥ 70% (기존 기준). 주장 표본은 주어·목적어·관계별 정확도를 보고만 한다 |
| R1 | **가지 정확도 최소 개선**: ① 관계 근거 단계(사실 확인/반복 관측/가설)를 `EdgeEvidence → Claim.evidence_status`로 읽기 쪽에서 계산 (`confirmed` 규칙은 그대로) ② 자동 확장이 가설만 있는 관계·일반 노드(PLACE·넓은 TOPIC)를 넘지 않게 하고, 후보 순서를 근거 단계·독립 근거 수로 정함 ③ 중복 키 병합(DRAM·DDR·DDR5, 키 없는 개체) — 노드 `merged` 상태는 있으나 병합 도구 없음 ④ 검토 대기 노드 승인·제외 명령 | E1 사본에서 뿌리(NVDA·HBM·메모리 3사)로 확장한 상위 30개 노드·경로를 소유자가 표시: 원문이 관계를 뒷받침 ≥ 70%, 중복 노드 ≤ 10%, 모든 노드에 경로·발췌 있음(자동 검사 100%) |
| R2 | **과거 시점 재현**: 하루씩 `FixedClock`을 그 날 끝으로 두고 그때까지 게시된 글만 그래프에 반영·확장하는 재생 실행 (읽기 쪽 as_of는 이미 있음) | 재생한 t 시점 상태 = t까지 게시된 글만으로 새로 만든 상태(자동 테스트). `available_at > t` 행 0. 두 번 돌려 결과 같음 |
| R3 | **노드별 내러티브 시계열 ↔ 시세**: 노드·일별 언급 수(`NodeMention`), 독립 작성자 수, 주장 수·주장별 태도(`Claim`)를 `closes_at` 기준 거래일에 맞춰 일봉(`PriceBar`, 거래량 포함)과 붙임. E1 집계 코드를 일반화 | E1 신호(B0·N1)를 이 경로로 다시 계산해 E1 스크립트와 같은 값. 발견된 상장 노드 중 시세가 있는 비율을 보고 (현재 미국·한국만, 20종목 상한) |
| R4 | **Opportunity Radar MVP** (신호 2개, 가격·거래량만): ① 선행 발견 — 노드의 내러티브(독립 작성자·주장)는 늘지만 같은 기간 주가 반응이 작음 ② 확산 초기 — 그 노드에서 새 관계·새 가지가 빠르게 생김. 기회마다 발견 경로, 근거 발췌, 반대 근거(부정 태도 주장), 시장 반응을 함께 보임. 매매 판단 없음 | R2 재생으로 1년 과거 검증: 신호가 난 노드의 이후 5·20거래일 초과수익을 무작위 노드·언급량(B0) 기준과 비교, 순열 검정 p < 0.1. 그 뒤 조정 없이 포워드 8주 이상에서 방향이 뒤집히지 않음 |
| R5 | **수급**: 소유자가 소스를 승인한 뒤 한국 종목 투자 주체별 매매부터. 미국은 같은 성격의 일별 자료가 확인되기 전까지 넣지 않음(추정 금지) | 결측 거래일 < 5%, 원천 값 대조 표본 일치. 수급 확인 신호는 R4와 같은 방식으로 검증 |
| R6 | 과열 경고·내러티브 붕괴: 반박 주장 탐지(`verification_status`는 있으나 쓰는 곳 없음)와 위험 신호가 필요. R4가 기준을 넘은 뒤 | R4와 같은 과거·포워드 검증 |

알려진 한계:

- 과거 1년 수집은 NVIDIA·메모리 검색어로 받은 것이다. 가지가 새 검색어로 수집을 넓히는 것은 앞으로(포워드)만 가능하고, 과거 검증은 기존 수집 범위 안의 발견만 본다.
- 시세는 미국·한국만 받는다(D27). TSMC(TW) 같은 노드는 R3에서 "시세 없음"으로 두고 추정하지 않는다.
- 내러티브 묶음(`Narrative`)은 실데이터에서 0건이다. R3·R4는 노드 단위 시계열로 시작한다.
