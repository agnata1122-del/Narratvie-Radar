# 로드맵

PRD 19장(Phase)과 23장(Step)을 따르되, 섀도 테스트용 포워드 데이터를 하루라도 빨리 쌓기 위해 수집기를 앞당겼다([DECISIONS.md](DECISIONS.md) D2). 첫 소스는 공식 API가 있는 Bluesky와 Hacker News다(D15). 디시·네이버는 데이터 이용 문의 회신 후 추가한다.

첫 데모 목표: 같은 관심사를 며칠 뒤 다시 열었을 때, 무엇이 달라졌고 왜 그렇게 말할 수 있는지를 근거와 함께 바로 이해한다.

## 체크포인트

1. **M3 이후**: 수집기가 24시간 연속으로 돌고, 누락률·스냅샷 재방문 성공률·공백 기록을 확인한다.
2. **M7 이후**: 명령줄만으로 수집 → 분류 → 그래프 → 위키 → 시점 복원이 끝까지 돌고, 평가 리포트가 나온다.
3. **M9 이후**: 브라우저에서 "달라진 점"과 시간 재생 화면을 스크린샷으로 확인한다.

## 시작 전에 필요한 것

- **네트워크 허용** (M2): 개발 환경에서 `jetstream1.us-east.bsky.network`, `jetstream2.us-east.bsky.network`, `hn.algolia.com`, `hacker-news.firebaseio.com`에 접속할 수 있어야 한다. 안 되면 확인 명령은 로컬 PC에서 실행한다.
- **데이터 보관** (M3): 세션 사이에 수집 데이터를 보관할 비공개 저장소. 클라우드 세션만으로 운영한다(DECISIONS D16).
