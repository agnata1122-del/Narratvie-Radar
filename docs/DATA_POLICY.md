# 데이터 수집·이용 정책

이 문서는 수집기를 켜기 전에 반드시 지켜야 할 규칙과, 소스별 이용 조건 확인 결과를 기록한다.

## 1. 확인 결과 (2026-10-16)

이 개발 환경에서는 두 사이트의 약관 원문 페이지에 접속하지 못해 검색 결과로 확인했다. **수집기를 켜기 전에 프로젝트 소유자가 원문을 직접 확인해야 한다.**

### 디시인사이드 (미국주식갤러리)

- 현행 가입 약관의 금지 행위에 "자동화된 수단을 이용하여 서비스에 게재된 콘텐츠를 비롯한 기타 정보를 수집하거나 인공지능(AI) 학습을 목적으로 수집, 이용하는 행위"가 있다.
- 회사의 사전 승낙 없이 서비스에서 얻은 정보를 영리 목적으로 복제·전송·배포하거나 제3자에게 이용하게 하는 행위도 금지한다.
- 게시물 저작권은 게시한 이용자에게 있다.
- 원문: <https://sign.dcinside.com/join/agree>, <https://nstatic.dcinside.com/company/rules/service_policy.html>
- **판단**: 허락 없는 자동 수집은 약관 위반이다.

### 네이버페이 증권 (종목토론)

- 공식 종목토론 API가 있지만 증권사 대상으로 제공된다(리포트 제공을 대가로 약 20개 증권사가 이용, 2022년부터 무단 사용 증권사에 중단 요청).
- 증권 서비스 약관에서 자동 수집 조항 원문은 찾지 못했다. 네이버는 일반적으로 약관과 정책에서 크롤링을 금지한다고 알려져 있다.
- NVDA 토론은 국내 종목토론실이 아니라 해외주식 토론(모바일)에 있다.
- **판단**: 개인이 받을 수 있는 공식 경로가 없고, 자동 수집 허용 여부가 불명확하다.

## 2. 결정

- **먼저 공식 API 소스(Bluesky, Hacker News)로 시작한다.** 약관 문제 없이 실제 서사로 파이프라인을 만들고 포워드 데이터를 쌓는다. 이 소스의 원문은 `content_access_status = permitted`로 저장한다.
- 디시·네이버는 두 회사에 데이터 이용 문의를 보내고([outreach/](outreach/)) 회신을 기다린다. 프로젝트 소유자는 위 확인 결과와 약관 위반 위험을 인지하고 있으며, 이 두 소스를 켤 때는 아래 규칙을 지킨다. 허락을 받으면 이 문서의 상태를 갱신한다.
- 영어권 소스라 미주갤의 한국 개인투자자 서사와 다르다. 화면과 평가에서 "어느 커뮤니티에서 관측된 것인지"를 항상 밝힌다.

## 3. 수집기가 지켜야 할 규칙

이 규칙은 코드로 강제하고 테스트로 확인한다.

1. **읽기 전용**: 글쓰기, 댓글, 추천, 로그인 기능을 만들지 않는다.
2. **저빈도**: 소스별 요청 간격 3초 이상, 동시 요청 1개. 목록 폴링은 1–2분 간격.
3. **정직한 User-Agent**: 프로젝트 이름과 저장소 주소를 밝힌다. 브라우저로 위장하지 않는다.
4. **robots.txt 확인**: 수집 전에 확인하고, 금지된 경로는 요청하지 않는다.
5. **문제가 생기면 바로 멈춤**: 첫 번째 문제에서 즉시 멈추고, 그 소스에는 더 이상 요청하지 않는다.
   - 차단 신호(401·403·429, 캡차·차단 안내 페이지, 로그인 페이지로 이동) → `blocked`
   - 그 밖의 문제(다른 4xx, 5xx, 타임아웃·연결 오류, robots.txt 확인 불가, 페이지 구조가 달라 파싱 실패) → `stopped`
   - 예외: 삭제된 글(404·410)은 흔하므로 문제로 보지 않는다.
   - 멈추면 `live_enabled`도 꺼진다. 재개는 사람이 원인을 확인한 뒤 `nr sources reset --reason ...` → `nr sources enable`로 한다.
   - 프록시 회전, IP·VPN 서버 변경, 캡차 풀이 같은 우회는 하지 않는다.
6. **VPN**: 수집기를 실행하는 PC의 네트워크(VPN 포함)는 운영자가 정한다. 수집기는 시스템 네트워크를 그대로 쓰며, IP를 바꾸거나 여러 IP를 돌려 쓰는 기능은 없다. 수집이 멈춘 뒤 VPN 서버나 IP를 바꿔 재개하는 것은 차단 우회이므로 하지 않는다.
   - User-Agent에 프로젝트 이름과 저장소 주소가 들어가므로 VPN을 써도 수집 주체는 드러난다(3번 규칙).
   - VPN 출구 IP는 데이터센터 대역인 경우가 많아 차단이나 캡차가 더 자주 나올 수 있다. 그때 수집기는 5번 규칙대로 바로 멈춘다.
7. **기본값은 꺼짐**: 전체 스위치(`NR_LIVE_COLLECTION_ENABLED`)와 소스별 `live_enabled`가 모두 켜져 있어야 수집한다.
8. **작성자 정보 최소화**: 작성자 ID·닉네임·IP 원문을 저장하지 않는다. `author_hash = HMAC(salt, source + 작성자)`만 저장한다. salt는 `NR_AUTHOR_HASH_SALT`로 주입하고 저장소에 넣지 않는다.
   - 예외: 글 주소 자체에 계정 ID가 들어가는 소스(Bluesky의 `at://계정ID/...`, `bsky.app/profile/계정ID/post/...`)는 근거 링크와 삭제 처리를 위해 그 주소를 저장한다. 작성자 기준 조회·집계는 `author_hash`로만 하고, 주소에서 계정 ID를 뽑아 쓰지 않는다.
9. **원문은 로컬에만**: 원문은 로컬 DB(`data/`)에만 저장한다. 공개 저장소에 실제 게시글, 골드셋, DB 파일을 커밋하지 않는다.
10. **보여주는 범위**: 외부 테스터 화면에는 짧은 발췌, AI 요약, 원문 링크만 보여준다. 원문 전체를 재배포하지 않는다.
11. **상업적 이용 전 재확인**: 유료화나 외부 API 제공 전에 반드시 권한을 다시 확인한다.
12. **삭제 반영**: 출처에서 글이 지워진 것을 알게 되면 원문(본문, 제목, 댓글, 발췌)을 지우고 삭제 사실과 시각만 남긴다. 그 글에서 나온 집계·관계 이력은 남기되 원문을 다시 보여주지 않는다.

웹 페이지가 아닌 실시간 스트림(Bluesky Jetstream)에서는 2·4번 규칙 대신 "연결 하나만 유지하고, 서버가 거부하거나 연결이 끊기면 5번 규칙대로 멈춘다"를 적용한다.

## 4. 소스 상태

화면과 API는 소스마다 다음 상태 중 하나를 표시한다. 수집이 실제로 되지 않는 소스를 라이브처럼 보이게 하지 않는다(PRD 21장).

| 상태 | 의미 |
|---|---|
| `not_authorized` | 어댑터는 있지만 수집하지 않음 (기본값) |
| `test_mode` | 수동 import 등으로 넣은 데이터만 있음 |
| `live` | 라이브 수집 중 |
| `paused` | 사람이 멈춤 |
| `blocked` | 차단 신호를 감지해 자동으로 멈춤 |
| `stopped` | 오류(5xx, 연결 실패, 파싱 실패 등)로 자동으로 멈춤 |
